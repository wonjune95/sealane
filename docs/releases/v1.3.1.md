# Sealane v1.3.1

## Fixes from using it on a live cluster

### Highlights
- **Route check flags a port the Service does not expose**: a request to `http://echo.ns.svc.cluster.local/` used to show "matched" although the Service only exposes 8080, and the real request then got a bare 503. The destination now shows a red "Port 80 not exposed (service ports: 8080)" pill and a note that Envoy will answer 503. The port checked is the destination's `port.number`, else the URL's port, else 80 for http and 443 for https.
- **Request console explains Envoy's own 503**: a `503` from `server: envoy` with no `x-envoy-upstream-service-time` now comes with a hint: no cluster for this host and port — check that the Service exposes the port and the VirtualService destination matches.
- **Service view shows problems on its own resources**: a Service page no longer says "Nothing wrong with this service's routing" while a Gateway bound by its VirtualService has no pods; findings on every VirtualService, DestinationRule, HTTPRoute and Gateway listed on the page are included.
- **Quieter VirtualService form**: a match without a URI no longer shows an empty `uri —` row (a "+ URI" link adds one, its × removes it, and "Add match" starts empty), and the weight input only appears once a rule has two or more destinations.

### Upgrade notes
- No breaking changes; values, environment variables and existing sessions keep working.
- `helm upgrade sealane oci://ghcr.io/wonjune95/charts/sealane --version 1.3.1 -n <namespace> --reset-then-reuse-values` — details in [Upgrading](https://wonjune95.github.io/sealane/upgrading/).
