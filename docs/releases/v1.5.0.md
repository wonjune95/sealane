# Sealane v1.5.0

## Sidecar check, findings that open the field, Services filter

### Highlights
- **Sidecar-injection check.** The mesh analysis warns (`namespace-injection-no-sidecar`) when a namespace has sidecar injection on (`istio-injection=enabled`, or an `istio.io/rev` label with no `istio-injection` label) but running pods lack an `istio-proxy` — typically pods that started before the label was set. Kubernetes native sidecars (`istio-proxy` as an init container, as Istio 1.22+ injects on recent clusters) count as sidecars; pods opted out with `sidecar.istio.io/inject: "false"` are ignored.
- **Findings open the offending field.** A finding's resource link now opens the YAML tab scrolled to the field it is about, highlighted, with a banner naming the path; the Analysis page and the Service view both use it.
- **Services list filter.** "Only services with mesh config" hides the rows with no routes, rules, policies or findings; the header shows "N of total" while the filter is on.

### Upgrade notes
- No breaking changes; existing sessions stay valid. The chart is unchanged apart from the version (the ClusterRole already allows listing namespaces).
- `helm upgrade sealane oci://ghcr.io/wonjune95/charts/sealane --version 1.5.0 -n <namespace> --reset-then-reuse-values`
