# Sealane v0.8.0 Implementation Plan — 리네임 + 영어 UI + 프로젝트 외형

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `istio_dashboard`를 `Sealane`으로 리네임하고, UI를 영어 기본 + 한국어 로케일로 바꾸고, 공개 오픈소스 프로젝트의 기본 파일을 갖춰 `v0.8.0`을 발행한다.

**Architecture:** 이름은 Go 모듈·바이너리·이미지·차트·쿠키·CM/Secret 기본값까지 한 번에 바꾸되, 기존 설치는 values로 옛 CM/Secret 이름을 지정해 데이터를 유지한다. i18n은 라이브러리 없이 `web/src/i18n/index.ts`의 `t(key, vars)` 하나와 `en.json`/`ko.json`으로 한다. 로케일 전환은 저장 후 전체 리로드(클러스터 전환과 같은 패턴)라 Provider/Context가 필요 없다. 한국어 유출은 `hack/check-i18n.sh`가 CI에서 막는다.

**Tech Stack:** Go 1.26, React 18 + TypeScript + Vite, Helm 3, GitHub Actions, Playwright(픽스처 기반 브라우저 테스트).

**Spec:** `docs/superpowers/specs/2026-10-13-sealane-open-source-design.md` §4 (v0.8.0). 스펙과 다른 점 하나: 스펙은 `LocaleProvider`/`useT()`를 적었지만 이 계획은 모듈 전역 `t()` + 토글 시 리로드로 같은 동작을 더 적은 코드로 구현한다.

## Global Constraints

- 저장소 `github.com/wonjune95/sealane`, Go 모듈 `github.com/wonjune95/sealane`, 이미지 `ghcr.io/wonjune95/sealane`, 차트 `charts/sealane`(name `sealane`), 차트 version/appVersion `0.8.0`.
- 런타임 이름: 쿠키 `sealane_session`, 계정 경로 `/etc/sealane/accounts`, values 기본 `accountsConfigMap: sealane-accounts`, `clustersSecret: sealane-clusters`, 데모 ns `sealane-demo`, 테스트 env `SEALANE_TEST_URL`/`SEALANE_CHROMIUM_PATH`, localStorage 키 `sealane-theme`/`sealane-cluster`/`sealane-ns`/`sealane-locale`.
- 제품 표기: "Sealane" (브랜드명은 번역하지 않음). 부제 "Routing console for Istio and Gateway API". README의 비제휴 고지 유지.
- 번역하지 않는 것: 브랜드명, Kubernetes kind/필드명, 코드·명령·URL·env 이름, 에러 reason 코드(`BadRequest` 등).
- 한국어는 `web/src/i18n/ko.json`, `README.ko.md`, `docs/superpowers/` 안에만 존재한다. 그 외 어디서든 한글이 나오면 `hack/check-i18n.sh`가 실패한다.
- Go 사용자 노출 문자열·주석, TS 주석, 차트·예시·워크플로 주석은 영어.
- 커밋 메시지는 이 계획부터 영어·명령형(공개 프로젝트 관행). `Co-Authored-By` 트레일러를 붙이지 않는다(사용자 규칙).
- 의존성 추가 없음. 새 테스트 프레임워크 없음.
- 옛 GHCR 패키지(`istio-dashboard`)는 지우지 않는다.
- 라이브 설치(CI/CD 클러스터 ns `istio-dashboard`)는 Task 12 절차로만 옮긴다. 다른 네임스페이스·릴리스는 건드리지 않는다.

`web/src/i18n/index.ts`:
```ts
import en from './en.json'
import ko from './ko.json'

export type Locale = 'en' | 'ko'
export type Key = keyof typeof en
const KEY = 'sealane-locale'
const DICT: Record<Locale, Record<string, string>> = { en, ko }

function detect(): Locale {
  try {
    const saved = localStorage.getItem(KEY)
    if (saved === 'en' || saved === 'ko') return saved
  } catch {
    /* storage unavailable */
  }
  return navigator.language?.toLowerCase().startsWith('ko') ? 'ko' : 'en'
}

// Resolved once per page load. Switching writes the choice and reloads (same
// pattern as cluster switching), so no provider/context is needed.
export const locale: Locale = detect()

export function t(key: Key, vars?: Record<string, string | number>): string {
  let s = DICT[locale][key] ?? DICT.en[key] ?? key
  if (vars) for (const [k, v] of Object.entries(vars)) s = s.split(`{${k}}`).join(String(v))
  return s
}

export function setLocale(next: Locale) {
  try {
    localStorage.setItem(KEY, next)
  } catch {
    /* storage unavailable */
  }
  window.location.reload()
}
```

- [ ] **Step 6: 셸 컴포넌트를 `t()`로 전환**

변환 규칙(이후 모든 Task에 적용):
- JSX 텍스트 `<span>텍스트</span>` → `<span>{t('key')}</span>`
- 속성 `aria-label="텍스트"` → `aria-label={t('key')}`
- 템플릿 리터럴 `` `${name} 클러스터를 등록했습니다` `` → `t('key', { name })` + 사전 값 `"{name} 클러스터를 등록했습니다"`
- 조건식 `theme === 'dark' ? '라이트 모드' : '다크 모드'` → `theme === 'dark' ? t('theme.light') : t('theme.dark')`
- 모듈 상단 상수 배열(`LINKS`, `PAGE_NAMES`)은 label에 **키**를 넣고 렌더 시 `t(l.label)`; 타입은 `Key`.
- `<br/>`로 나뉜 문장은 줄마다 키 하나(`login.headline1/2`).
- `<code>{name}</code>`처럼 JSX 요소가 문장 가운데 끼면 앞/뒤 키 두 개(`diff.dangerBefore/After`).

**English** | [한국어](README.ko.md)

![Kubernetes](https://img.shields.io/badge/Kubernetes-native-326CE5?logo=kubernetes&logoColor=white)
![Istio](https://img.shields.io/badge/Istio-%2FGateway%20API-466BB0?logo=istio&logoColor=white)

> Sealane is a third-party tool for Istio. It is not an official Istio or CNCF project and is not affiliated with or endorsed by them.

**Sealane is a routing console for Istio and Gateway API.** It is a single-binary web UI that lets you browse, create and edit `VirtualService`, `HTTPRoute`, `DestinationRule`, `Gateway`, `AuthorizationPolicy` and the rest of the Istio and Gateway API resources through schema-driven forms or YAML, with dry-run validation, diff preview and role-based accounts, and no CRDs or operators installed in your cluster.

helm install sealane oci://ghcr.io/wonjune95/charts/sealane --version 0.8.0 -n sealane --create-namespace

![Sealane home](docs/img/screenshot.png)

> Upgrading from **Istio Dashboard** (the project's previous name)? See [docs/upgrading.md](docs/upgrading.md) — your accounts and clusters carry over.

---

## TL;DR

- **Local accounts and roles** — users live in one ConfigMap (`user: "role:bcryptHash"`); login issues an HMAC-signed session cookie. Cluster calls run as the pod's ServiceAccount; the app role (`admin` / `editor` / `viewer`) decides who may change what. A first boot creates `admin`/`admin` and forces a password change.
- **Writes are guarded** — every write is dry-run validated, previewed as a `kubectl diff`-style change, and checked against `resourceVersion` so a 409 shows *your copy vs the server's*. High-risk kinds require typing the resource name. Every change made through the UI lands in the change history with the account name.
- **Stateless, air-gapped** — React is embedded in the Go binary; sessions are signed cookies, so N replicas scale horizontally and nothing is fetched from the internet at runtime.
- **Generic resource engine** — dynamic-client based; 12 Istio kinds and 7 Gateway API kinds share one CRUD pipeline, and only CRDs present in the cluster are shown.
- **Traffic flow map** — draws ingress/egress paths from routing config alone; broken paths (missing service, zero endpoints) show as red edges.
- **Request console** — *Check route* computes which rule a request would hit without sending traffic; *Send* (opt-in, admin only) runs the request from inside a pod you pick so you see the real sidecar behavior.
- **Multi-cluster** — paste a kubeconfig to register a remote cluster; credentials stay in the host cluster's Secret and nothing is installed on targets.
- **English UI with a Korean locale** — switch from the header.

# Upgrading

## From Istio Dashboard (≤ 0.7) to Sealane (0.8)

Sealane is the new name of Istio Dashboard. Images, charts and default resource names changed; your data did not. Accounts live in the accounts ConfigMap and remote clusters in the clusters Secret, and both survive the move.

1. Install the new release next to the old one, pointing it at the existing ConfigMap and Secret:

   ```bash
   helm install sealane oci://ghcr.io/wonjune95/charts/sealane --version 0.8.0 -n <namespace> \
     --set accountsConfigMap=istio-dashboard-accounts \
     --set clustersSecret=istio-dashboard-clusters \
     --reuse-values   # drop this flag; copy any custom values (requestTester.enabled, image.*, resources) explicitly
   kubectl -n <namespace> rollout status deploy/sealane
   ```

2. Point your HTTPRoute or Ingress backend at the `sealane` Service (port 8080) and open the UI. Existing accounts work unchanged; everyone signs in again once because the session cookie was renamed.

3. Remove the old release: `helm uninstall istio-dashboard -n <namespace>`. The ConfigMap and Secret are not managed by Helm and stay in place.

If you prefer the new default names, rename the resources (`kubectl get cm istio-dashboard-accounts -o yaml | sed 's/istio-dashboard-accounts/sealane-accounts/' | kubectl apply -f -`, same for the Secret) and drop the two `--set` flags.

- Image: `ghcr.io/wonjune95/sealane` (the old `istio-dashboard` package stays but will not get new tags).
- Chart: `oci://ghcr.io/wonjune95/charts/sealane`, source under `charts/sealane`.
- UI language: English by default, Korean available from the header toggle (browser language is detected).
- Accounts mount path inside the pod: `/etc/sealane/accounts`.
