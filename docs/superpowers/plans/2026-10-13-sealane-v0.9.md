# Sealane v0.9.0 Implementation Plan — 어디서나 설치 (release engineering + quality gates)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Sealane을 어떤 클러스터에서든 세 가지 경로(Helm OCI, `kubectl apply -f install.yaml`, Artifact Hub)로 믿고 설치할 수 있게 만들고, CI에 품질 게이트(lint·취약점·CodeQL·Scorecard·Dependabot)와 kind+Istio e2e를 넣어 `v0.9.0`을 발행한다.

**Architecture:** 이미지는 `--platform=$BUILDPLATFORM` 빌드 스테이지 + Go 크로스 컴파일로 amd64/arm64 매니페스트 리스트를 만들고, 릴리스 워크플로가 cosign keyless 서명·SBOM·`install.yaml`·GitHub Release까지 한 잡에서 처리한다. 차트는 values 스키마·README·NOTES·Ingress/HTTPRoute·안정적 세션 Secret(`lookup`)을 얻고 Artifact Hub 메타데이터를 싣는다. 앱은 `/readyz`를 실제 API 서버 핑으로 바꾸고 버전을 노출한다. e2e는 CI에서 kind + Gateway API CRD + istioctl minimal 위에 차트를 설치하고 `hack/e2e.sh`가 curl로 로그인→비밀번호 변경→dry-run→생성→목록→흐름도→삭제를 검증한다.

**Tech Stack:** Go 1.26, React/Vite, Helm 3, Docker buildx, GitHub Actions(docker/build-push-action, sigstore/cosign-installer, anchore/sbom-action, aquasecurity/trivy-action, softprops/action-gh-release, golangci-lint v2, govulncheck, CodeQL, OSSF Scorecard, helm/kind-action), kind, istioctl 1.31.1, Gateway API v1.5.1, curl + jq.

**Spec:** `docs/superpowers/specs/2026-10-13-sealane-open-source-design.md` §5 (v0.9.0). 전제: v0.8.0 태그가 발행되어 있다(사용자가 푸시). 이 계획은 저장소 `/home/rocky/sealane`, 브랜치 `sealane-v0.9`(main에서 분기)에서 실행한다.

## Global Constraints

- 이름·경로: 이미지 `ghcr.io/wonjune95/sealane`, 차트 `oci://ghcr.io/wonjune95/charts/sealane`, 차트 소스 `charts/sealane`, 릴리스 자산 `install.yaml`·`sbom.spdx.json`·`sealane-<ver>.tgz`. 설치 네임스페이스 기본 `sealane`.
- 차트 version/appVersion `0.9.0`. 기존 values 키 이름은 유지(`image.*`, `imagePullSecrets`, `replicaCount`, `istioNamespace`, `service.*`, `accountsConfigMap`, `clustersSecret`, `requestTester.enabled`, `resources`, `serviceMonitor.enabled`). 새 키: `sessionSecret.{create,existingSecret}`, `ingress.{enabled,className,annotations,hosts,tls}`, `httpRoute.{enabled,annotations,parentRefs,hostnames}`. `values.schema.json`은 최상위 `additionalProperties: false`.
- 멀티아치 `linux/amd64,linux/arm64`; 서명은 cosign keyless(GitHub OIDC, 키 없음); SBOM SPDX JSON; Trivy는 실패시키지 않음(`exit-code: "0"`).
- `install.yaml` = `helm template sealane charts/sealane --namespace sealane --set sessionSecret.create=false --set image.tag=<ver>` 앞에 `Namespace sealane` 매니페스트. 모든 네임스페이스 리소스는 `metadata.namespace: {{ .Release.Namespace }}`를 가진다(`kubectl apply -f install.yaml`을 `-n` 없이 실행해도 `sealane`에 들어가도록).
- `/readyz`: 로컬 API 서버 `ServerVersion()` 핑, 타임아웃 2초, 실패 시 503. `/healthz`는 그대로 200.
- 버전: `var version = "dev"`(`cmd/server/main.go`), `-ldflags "-X main.version=<ver>"`, `--version` 플래그, `/api/capabilities`의 `appVersion`, 설정 페이지 하단 표시.
- CI: `ci.yml`에 golangci-lint(표준 린터), govulncheck, helm lint/template 추가; 별도 `codeql.yml`, `scorecard.yml`, `e2e.yml`; `.github/dependabot.yml`(gomod/npm/github-actions 주간, 그룹). 모든 액션은 `owner/repo@<40자 SHA> # vX` 형식으로 고정.
- e2e: kind + Gateway API `v1.5.1` CRD + `istioctl 1.31.1 --set profile=minimal` + `helm install` + `hack/e2e.sh`(bash, curl, jq만). 로컬 검증은 CI/CD 클러스터의 일회용 네임스페이스 `sealane-e2e`에서 한다(다른 네임스페이스는 건드리지 않는다).
- 문서·주석·커밋은 영어, 커밋 메시지 명령형, `Co-Authored-By`/`Signed-off-by` 트레일러 없음. 한국어는 `web/src/i18n/ko.json`, `README.ko.md`, `docs/superpowers/`에만(`./hack/check-i18n.sh`가 CI에서 검사).
- Go 명령은 `./cmd/... ./internal/...` 범위로(`web/node_modules`에 Go 패키지가 있음). 의존성 추가 없음(Go·npm 모두).
- 푸시·태그·GitHub 설정(Artifact Hub 등록, DCO 앱)은 사용자가 한다. 계획의 "사용자 단계"는 그렇게 표시한다. 클러스터·레지스트리를 건드리는 검증 명령(Harbor push, 일회용 네임스페이스 설치)은 컨트롤러가 직접 실행해도 된다.

import (
	"net/http"
	"net/http/httptest"
	"testing"

	"k8s.io/client-go/rest"
)

func TestReady(t *testing.T) {
	srv := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		if r.URL.Path != "/version" {
			http.NotFound(w, r)
			return
		}
		w.Header().Set("Content-Type", "application/json")
		_, _ = w.Write([]byte(`{"major":"1","minor":"34","gitVersion":"v1.34.0"}`))
	}))
	defer srv.Close()

	f, err := newFactory(&rest.Config{Host: srv.URL})
	if err != nil {
		t.Fatalf("newFactory: %v", err)
	}
	if err := f.Ready(); err != nil {
		t.Fatalf("Ready() against a healthy API server: %v", err)
	}

	down, err := newFactory(&rest.Config{Host: "http://127.0.0.1:1"})
	if err != nil {
		t.Fatalf("newFactory: %v", err)
	}
	if err := down.Ready(); err == nil {
		t.Fatal("Ready() against an unreachable API server must fail")
	}
}
```

// Ready is the readiness probe: the local API server must answer a version request
// within 2s, so a pod that cannot reach the cluster never receives traffic.
func (f *ClientFactory) Ready() error {
	cfg := rest.CopyConfig(f.baseCfg)
	cfg.Timeout = 2 * time.Second
	disc, err := discovery.NewDiscoveryClientForConfig(cfg)
	if err != nil {
		return err
	}
	_, err = disc.ServerVersion()
	return err
}
```

# publish the Helm chart to GHCR, render install.yaml and create the GitHub Release.
name: release

on:
  push:

      - uses: docker/setup-qemu-action@<sha> # v3
      - uses: docker/setup-buildx-action@<sha> # v3

            install.yaml

- [ ] **Step 1: hack/e2e.sh**

```bash
#!/usr/bin/env bash
# End-to-end smoke test against a freshly installed Sealane (initial admin/admin account).
# Usage: hack/e2e.sh http://localhost:8080 [namespace-for-the-test-VirtualService]
# Needs: curl, jq. Exits non-zero on the first failed check.
set -euo pipefail
BASE=${1:?base url, e.g. http://localhost:8080}
NS=${2:-default}
TYPE=virtualservices.networking.istio.io
NAME=sealane-e2e
JAR=$(mktemp)
NEWPASS="E2e-Pass-$(date +%s)!"
trap 'rm -f "$JAR"' EXIT

fail() { echo "FAIL: $*" >&2; exit 1; }
# api <method> <path> [json-body] → prints "<status>\n<body>"
api() {
  local m=$1 p=$2 b=${3:-}
  if [ -n "$b" ]; then
    curl -s -o /tmp/e2e.body -w '%{http_code}' -b "$JAR" -c "$JAR" -X "$m" -H 'Content-Type: application/json' -d "$b" "$BASE$p"
  else
    curl -s -o /tmp/e2e.body -w '%{http_code}' -b "$JAR" -c "$JAR" -X "$m" "$BASE$p"
  fi
}
expect() { local want=$1 got=$2 what=$3; [ "$got" = "$want" ] || fail "$what: expected HTTP $want, got $got: $(head -c 300 /tmp/e2e.body)"; echo "ok  $what ($got)"; }

echo "== probes"
expect 200 "$(curl -s -o /tmp/e2e.body -w '%{http_code}' "$BASE/healthz")" "healthz"
expect 200 "$(curl -s -o /tmp/e2e.body -w '%{http_code}' "$BASE/readyz")" "readyz"

echo "== initial login and forced password change"
expect 200 "$(api POST /api/login '{"username":"admin","password":"admin"}')" "login admin/admin"
expect 200 "$(api GET /api/capabilities)" "capabilities"
[ "$(jq -r '.mustChangePassword' /tmp/e2e.body)" = "true" ] || fail "mustChangePassword should be true on first login"
expect 204 "$(api POST /api/account/password "{\"currentPassword\":\"admin\",\"newPassword\":\"$NEWPASS\"}")" "change password"
expect 200 "$(api POST /api/login "{\"username\":\"admin\",\"password\":\"$NEWPASS\"}")" "login with new password"
expect 200 "$(api GET /api/capabilities)" "capabilities after change"
[ "$(jq -r '.mustChangePassword // false' /tmp/e2e.body)" = "false" ] || fail "mustChangePassword should be false now"
[ "$(jq -r '.virtualServiceInstalled' /tmp/e2e.body)" = "true" ] || fail "Istio CRDs not detected"
[ "$(jq -r '.httpRouteInstalled' /tmp/e2e.body)" = "true" ] || fail "Gateway API CRDs not detected"
echo "    appVersion=$(jq -r '.appVersion' /tmp/e2e.body) istiod=$(jq -r '.istiodVersion // "n/a"' /tmp/e2e.body)"

echo "== VirtualService dry-run → create → list → flow map → delete"
VS=$(cat <<EOF
{"apiVersion":"networking.istio.io/v1","kind":"VirtualService","metadata":{"name":"$NAME","namespace":"$NS"},
 "spec":{"hosts":["e2e.example.com"],"http":[{"route":[{"destination":{"host":"e2e.$NS.svc.cluster.local"}}]}]}}
EOF
)
expect 200 "$(api POST "/api/resources/$TYPE?dryRun=true" "$VS")" "dry-run create"
expect 201 "$(api POST "/api/resources/$TYPE" "$VS")" "create"
expect 200 "$(api GET "/api/resources/$TYPE")" "list"
jq -e --arg n "$NAME" --arg ns "$NS" 'map(select(.name==$n and .namespace==$ns)) | length == 1' /tmp/e2e.body >/dev/null || fail "created VirtualService missing from list"
expect 200 "$(api GET /api/flowmap)" "flow map"
expect 204 "$(api DELETE "/api/resources/$TYPE/$NS/$NAME")" "delete"
expect 200 "$(api GET "/api/resources/$TYPE")" "list after delete"
jq -e --arg n "$NAME" 'map(select(.name==$n)) | length == 0' /tmp/e2e.body >/dev/null || fail "VirtualService still listed after delete"

echo "== viewer is read-only"
code=$(api PUT /api/accounts/e2e-viewer '{"role":"viewer","password":"Viewer-Pass-2026!"}'); [ "$code" = 200 ] || [ "$code" = 204 ] || fail "create viewer account: got $code"; echo "ok  create viewer account ($code)"
# the mounted accounts ConfigMap syncs within ~1 min: retry the viewer login
for i in $(seq 1 15); do code=$(api POST /api/login '{"username":"e2e-viewer","password":"Viewer-Pass-2026!"}'); [ "$code" = 200 ] && break; sleep 5; done
expect 200 "$code" "login as viewer"
expect 403 "$(api POST "/api/resources/$TYPE?dryRun=true" "$VS")" "viewer write is forbidden"
echo "ALL OK"
```
`chmod +x hack/e2e.sh`. 상태 코드는 핸들러가 진실이다: `POST /api/account/password` → 204, `DELETE /api/resources/...` → 204, `PUT /api/accounts/{name}` → 200 또는 204(둘 다 허용). 계정 생성은 마운트 동기화에 최대 1분이 걸리므로 viewer 로그인은 최대 75초 재시도한다.
