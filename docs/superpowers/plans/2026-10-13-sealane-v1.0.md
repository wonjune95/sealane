# Sealane v1.0.0 Implementation Plan — 정책 + 생태계

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 새 기능 없이 v0.10.x 위에 약속(버전·지원·호환 정책, 거버넌스, 채택사), 그 약속을 뒷받침하는 검증(Istio 2버전 e2e 매트릭스, v0.8→v1.0 업그레이드 잡), 0.10 리뷰에서 미룬 작은 수정, 파일 기반 릴리스 노트, 생태계 제출 준비물을 얹어 `v1.0.0`을 발행한다.

**Architecture:** 코드 변경은 `cmd/server/main.go`(종료 전 지연)와 `internal/api/{login,oidc}.go`(쿠키 Secure, 콜백 정리)뿐이다. 나머지는 문서(`docs/versioning.md`, `GOVERNANCE.md`, `ADOPTERS.md`, `ROADMAP.md`, `docs/releases/`), 워크플로(`e2e.yml` 매트릭스 + 업그레이드 잡, `release.yml`의 `body_path`), 스크립트(`hack/upgrade-check.sh`, `hack/landscape/build-logo.py`), 제출 준비물(`artifacthub-repo.yml`, `docs/announcement*.md`, `hack/ecosystem/`)이다.

**Tech Stack:** Go 1.26, Helm 3, GitHub Actions(kind + istioctl), mkdocs-material, Python 3 + fontTools 4.60(시스템 python3, 로고 텍스트→패스), oras(Artifact Hub 메타데이터 푸시, `~/bin/oras`).

**Spec:** `docs/superpowers/specs/2026-10-13-sealane-open-source-design.md` §7 (v1.0.0), §8.1(사용자 작업), §8.3(테스트 원칙: 1.0의 새 검사는 e2e 매트릭스 하나). 전제: v0.10.0 발행·라이브 적용 완료(2026-10-13), main에 Dependabot Go/Actions 묶음 머지됨(k8s 0.37.1, gateway-api 1.6.3, istio client-go 1.31.1), npm 메이저 묶음은 revert됨. 저장소 `/home/rocky/sealane`, 브랜치 `sealane-v1.0`(main에서 분기).

## Global Constraints

- 새 기능 없음. 의존성 추가 없음(Go·npm·GitHub Action 모두). 새 Action을 쓰지 않는다.
- 1.x 약속(이 계획이 처음 명문화): Helm values 키·의미, 환경변수, 플래그, 계정 ConfigMap(`user: "role:bcryptHash"`)·클러스터 Secret 형식은 1.x 안에서 비호환 변경 금지(폐기는 한 minor 전에 예고). `/api/*`는 UI 전용 내부 계약. 수정 릴리스는 최신 minor에만. 호환: Kubernetes 최근 3 minor, Istio 최근 2 minor, Gateway API v1.x standard channel. 릴리스 주기 고정 안 함.
- e2e 매트릭스: Istio `1.30.5`와 `1.31.1`(2026-10-13 기준 각 라인 최신 패치), Gateway API CRD `v1.5.1` 공통, kind `kindest/node:v1.35.0`(기존 다이제스트 유지). 두 잡 모두 녹색이어야 1.0 게이트 통과.
- 업그레이드 잡: 0.8.0 차트(`oci://ghcr.io/wonjune95/charts/sealane --version 0.8.0`, 공개 이미지 `ghcr.io/wonjune95/sealane:0.8.0`)를 kind에 설치한 뒤 로컬 차트로 `--reset-then-reuse-values` 업그레이드. 0.8.0 차트는 `istio-system` 네임스페이스가 없으면 설치가 실패하므로 빈 네임스페이스를 먼저 만든다.
- 환경변수 추가는 `SHUTDOWN_DELAY`(기본 `5s`, `time.ParseDuration` 형식) 하나. 차트 값 추가 없음(필요하면 `extraEnv`로).
- 쿠키 `Secure`는 `OIDC_REDIRECT_URL`이 `https://`로 시작할 때만 켠다(라이브는 http nip.io라 기본은 꺼짐). 세션 쿠키와 상태 쿠키 둘 다.
- 릴리스 노트는 `docs/releases/vX.Y.Z.md`가 필수. 없으면 release 워크플로가 실패한다(`body_path`). 자동 생성 노트는 그 뒤에 붙는다.
- 모든 액션은 `owner/repo@<40자 SHA> # vX` 유지. 기존 SHA를 바꾸지 않는다.
- 한국어는 `web/src/i18n/ko.json`, `README.ko.md`, `docs/superpowers/`, 그리고 이 계획이 추가하는 `docs/announcement.ko.md`에만(`hack/check-i18n.sh` 허용 목록에 한 줄 추가). `docs/announcement*.md`는 mkdocs `exclude_docs`로 사이트에서 뺀다.
- 사용자 이메일·회사명을 공개 파일에 적지 않는다. `artifacthub-repo.yml`의 `owners[].email`과 `repositoryID`, `ADOPTERS.md`의 회사명은 사용자가 확인한 뒤 채운다(그때까지는 그 사실을 문장으로 적는다).
- 커밋 영어·명령형, 트레일러 없음. Go 명령은 `./cmd/... ./internal/...` 범위(`./...` 금지). Ponytail: 가장 짧은 동작하는 diff.
- 클러스터·레지스트리·푸시·태그는 컨트롤러가 직접 실행한다(서브에이전트는 요청만). 서브에이전트는 kind·docker·kubectl을 쓰지 않는다.
- 검증 묶음(모든 태스크 공통): `go vet ./cmd/... ./internal/... && go test ./internal/...`, `go run github.com/golangci/golangci-lint/v2/cmd/golangci-lint@v2.14.0 run ./cmd/... ./internal/...`, `cd web && npm run build && npm run lint`, `./hack/check-i18n.sh`, `helm lint charts/sealane`, `/tmp/mkdocs-venv/bin/mkdocs build --strict`, 바뀐 워크플로 `python3 -c 'import yaml; yaml.safe_load(open("…"))'`.

### Task 2: e2e 매트릭스(Istio 1.30.5 / 1.31.1) + v0.8.0→로컬 차트 업그레이드 잡

**Files:**

**Interfaces:**

- Produces: 잡 이름 `kind-istio (1.30.5)`, `kind-istio (1.31.1)`, `upgrade-from-0.8`. Task 6의 1.0 게이트가 이 셋의 녹색을 확인한다.

- [ ] **Step 1: 매트릭스** — `e2e.yml`의 `env.ISTIO_VERSION`을 지우고 `kind-istio` 잡에:
```yaml
    strategy:
      fail-fast: false
      matrix:
        istio: ["1.30.5", "1.31.1"]
    env:
      ISTIO_VERSION: ${{ matrix.istio }}
```
  `KIND_CLUSTER`·`GATEWAY_API_VERSION`은 워크플로 env에 그대로 둔다(잡마다 러너가 다르므로 클러스터 이름 충돌 없음). 나머지 스텝은 그대로. Istio 1.30이 Gateway API v1.5.1 CRD에서 `istioctl install`에 실패하면(PR CI에서 확인) `matrix.include`로 1.30.5에만 `gateway_api: v1.4.0`을 주고 `GATEWAY_API_VERSION: ${{ matrix.gateway_api || 'v1.5.1' }}`로 바꾼다 — 이 분기를 쓴 경우 보고서에 적는다.
- [ ] **Step 2: `hack/upgrade-check.sh`** — 두 단계 스크립트. `hack/e2e.sh`의 `api`/`login_retry` 함수를 복사한다(공유 라이브러리로 빼지 않는다).
```bash
#!/usr/bin/env bash
# Upgrade check: run "pre" against a fresh 0.8.0 install, upgrade the chart, then run "post".
# Usage: hack/upgrade-check.sh pre|post http://localhost:8080 [state-file]
# pre : logs in as admin/admin, sets a new password, creates a viewer account, writes the state file.
# post: logs in with the state file's passwords (admin and viewer), checks appVersion changed and the viewer is still read-only.
set -euo pipefail
PHASE=${1:?pre|post}; BASE=${2:?base url}; STATE=${3:-/tmp/sealane-upgrade-state}
JAR=$(mktemp); BODY=$(mktemp); trap 'rm -f "$JAR" "$BODY"' EXIT
fail() { echo "FAIL: $*" >&2; exit 1; }
api() { local m=$1 p=$2 b=${3:-}; : >"$BODY"
  if [ -n "$b" ]; then curl -s --max-time 20 -o "$BODY" -w '%{http_code}' -b "$JAR" -c "$JAR" -X "$m" -H 'Content-Type: application/json' -d "$b" "$BASE$p" || true
  else curl -s --max-time 20 -o "$BODY" -w '%{http_code}' -b "$JAR" -c "$JAR" -X "$m" "$BASE$p" || true; fi; }
expect() { [ "$2" = "$1" ] || fail "$3: expected HTTP $1, got $2: $(head -c 300 "$BODY")"; echo "ok  $3 ($2)"; }
login_retry() { local code; for _ in $(seq 1 24); do code=$(api POST /api/login "{\"username\":\"$1\",\"password\":\"$2\"}"); [ "$code" = 200 ] && break; sleep 5; done; echo "$code"; }

case "$PHASE" in
pre)
  ADMIN_PASS="Up-Admin-$(date +%s)!"; VIEWER_PASS="Up-Viewer-$(date +%s)!"
  expect 200 "$(login_retry admin admin)" "login admin/admin (0.8.0)"
  expect 204 "$(api POST /api/account/password "{\"currentPassword\":\"admin\",\"newPassword\":\"$ADMIN_PASS\"}")" "change admin password"
  expect 200 "$(login_retry admin "$ADMIN_PASS")" "login with new admin password"
  code=$(api PUT /api/accounts/upgrade-viewer "{\"role\":\"viewer\",\"password\":\"$VIEWER_PASS\"}")
  { [ "$code" = 200 ] || [ "$code" = 204 ]; } || fail "create viewer: $code $(head -c 300 "$BODY")"
  expect 200 "$(api GET /api/capabilities)" "capabilities before upgrade"
  OLD=$(jq -r '.appVersion // ""' "$BODY")
  printf 'ADMIN_PASS=%s\nVIEWER_PASS=%s\nOLD_VERSION=%s\n' "$ADMIN_PASS" "$VIEWER_PASS" "$OLD" >"$STATE"
  echo "pre OK (appVersion before: ${OLD:-n/a})" ;;
post)
  # shellcheck disable=SC1090
  . "$STATE"
  expect 200 "$(login_retry admin "$ADMIN_PASS")" "admin password survived the upgrade"
  expect 200 "$(api GET /api/capabilities)" "capabilities after upgrade"
  NEW=$(jq -r '.appVersion // ""' "$BODY"); [ -n "$NEW" ] && [ "$NEW" != "$OLD_VERSION" ] || fail "appVersion did not change: '$OLD_VERSION' -> '$NEW'"
  [ "$(jq -r '.mustChangePassword // false' "$BODY")" = "false" ] || fail "admin forced to change password again after upgrade"
  expect 200 "$(login_retry upgrade-viewer "$VIEWER_PASS")" "viewer account survived the upgrade"
  expect 403 "$(api POST '/api/resources/virtualservices.networking.istio.io?dryRun=true' '{"apiVersion":"networking.istio.io/v1","kind":"VirtualService","metadata":{"name":"x","namespace":"default"},"spec":{"hosts":["x"]}}')" "viewer still read-only"
  echo "post OK (appVersion: $OLD_VERSION -> $NEW)" ;;
*) fail "phase must be pre or post" ;;
esac
```
  `chmod +x`. 참고: 0.8.0은 `appVersion`을 capabilities에 싣지 않으므로 `OLD`가 빈 문자열일 수 있다 — 그래서 비교는 “비어 있지 않고 다르다”. viewer의 403은 Istio CRD가 없어도 권한 검사가 먼저라 성립한다(현재 `internal/api`의 역할 미들웨어가 dryRun 전에 403을 낸다 — `go test ./internal/api/ -run Viewer`로 확인하고, 아니면 그 줄을 `GET /api/accounts`의 403으로 바꾼다).
- [ ] **Step 3: 업그레이드 잡** — `e2e.yml`에 추가:
```yaml
  upgrade-from-0.8:
    runs-on: ubuntu-latest
    timeout-minutes: 20
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
      - name: Build image
        run: docker build -t sealane:ci .
      - uses: helm/kind-action@1544676c07bb3570fcb70166beaa07c4528fd4aa # v1.15.1
        with:
          cluster_name: sealane-upgrade
          node_image: kindest/node:v1.35.0@sha256:452d707d4862f52530247495d180205e029056831160e22870e37e3f6c1ac31f
      - name: Install 0.8.0 from GHCR
        run: |
          kubectl create ns istio-system   # the 0.8.0 chart puts a Role there unconditionally
          helm install sealane oci://ghcr.io/wonjune95/charts/sealane --version 0.8.0 -n sealane --create-namespace --wait --timeout 180s
      - name: Seed accounts on 0.8.0
        run: |
          kubectl -n sealane port-forward svc/sealane 8080:8080 >/tmp/pf1.log 2>&1 &
          for i in $(seq 1 30); do curl -sf http://localhost:8080/healthz >/dev/null && break; sleep 1; done
          ./hack/upgrade-check.sh pre http://localhost:8080 /tmp/state
          kill %1
      - name: Upgrade to the local chart
        run: |
          kind load docker-image sealane:ci --name sealane-upgrade
          helm upgrade sealane charts/sealane -n sealane --reset-then-reuse-values \
            --set image.repository=sealane --set image.tag=ci --set image.pullPolicy=Never --wait --timeout 180s
          helm history sealane -n sealane
      - name: Verify after upgrade
        run: |
          kubectl -n sealane port-forward svc/sealane 8080:8080 >/tmp/pf2.log 2>&1 &
          for i in $(seq 1 30); do curl -sf http://localhost:8080/healthz >/dev/null && break; sleep 1; done
          ./hack/upgrade-check.sh post http://localhost:8080 /tmp/state
      - name: Logs on failure
        if: failure()
        run: |
          kubectl -n sealane logs deploy/sealane --tail=100 || true
          kubectl -n sealane get cm,secret,deploy,svc || true
          cat /tmp/pf1.log /tmp/pf2.log 2>/dev/null || true
```
