# Sealane v1.3.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship v1.3.0 "forms and lists": curated forms for VirtualService and DestinationRule, list summaries for every kind, sortable and paged lists, a warning-tinted Mesh analysis card on the home page, mobile table polish, and a CI job that runs the fixture-based browser tests.

**Architecture:** Curated forms follow the existing `FormIntegration` contract in `web/src/forms/registry.tsx` (`isRepresentable` / `toModel` / `fromModel` / `render`) that the HTTPRoute form already uses; anything the form cannot represent losslessly locks the Form tab and leaves YAML. List summaries extend `internal/k8s/summarize.go`'s `summarizers` map. Sorting and paging are client-side in the existing list pages. Browser tests stay fixture-based (`page.route` mocks) and run in CI against the Vite dev server.

**Tech Stack:** Go 1.25, React 18 + TanStack Query + Tailwind 3, Playwright (already in `web/devDependencies`), GitHub Actions. No new dependencies.

**Spec:** Decided in conversation on 2026-10-14 under the maintainer's delegation ("do those too, make the Mesh analysis card feel like a warning on the overview, then keep improving as a user"). `docs/versioning.md` 1.x promise applies.

- Commits: imperative subject, body explains why, **no trailers**.
- Backend messages English; UI labels localized; curated-form field labels may stay English where the HTTPRoute form keeps them English (field names are API terms).

### Task 3: VirtualService curated form

**Files:** `web/src/forms/virtualservice.ts` (new), `web/src/forms/VirtualServiceForm.tsx` (new), `web/src/forms/registry.tsx`, `web/src/api/subsets.ts` (new), `web/tests/vs-form.mjs` (new), `web/tests/README.md`, `package.json` (`test:vs-form`), i18n

**Contract (model):**

```ts
export interface VSMatchModel { uriType?: 'prefix' | 'exact' | 'regex'; uriValue?: string; headers: { name: string; type: 'exact' | 'prefix' | 'regex'; value: string }[] }
export interface VSDestinationModel { host: string; subset?: string; port?: number; weight?: number }
export interface VSRuleModel { name?: string; match: VSMatchModel[]; route: VSDestinationModel[]; timeout?: string; retries?: { attempts: number; perTryTimeout?: string }; rewriteUri?: string }
export interface VirtualServiceFormModel { name: string; namespace: string; hosts: string[]; gateways: string[]; http: VSRuleModel[] }
```

`isVSRepresentable(obj)`: `spec` keys ⊆ `{hosts, gateways, http, exportTo}` (exportTo preserved untouched by `fromModel`); every `http[]` entry keys ⊆ `{name, match, route, timeout, retries, rewrite}`; each `match[]` keys ⊆ `{uri, headers}` with `uri` keys ⊆ `{prefix, exact, regex}` (exactly one) and each header value keys ⊆ `{exact, prefix, regex}` (exactly one); each `route[]` keys ⊆ `{destination, weight}` with `destination` keys ⊆ `{host, subset, port}` and `port` keys ⊆ `{number}`; `retries` keys ⊆ `{attempts, perTryTimeout}`; `rewrite` keys ⊆ `{uri}`. Anything else (tls, tcp, fault, mirror, corsPolicy, headers manipulation, delegate, …) → not representable (YAML tab, same lock as HTTPRoute).

`toVSForm(obj)` / `fromVSForm(base, model)`: lossless for the representable subset; `fromVSForm` preserves metadata and `spec.exportTo`, drops empty strings, omits `match` when empty, omits `weight` when undefined, writes `destination.port = { number }` only when set, `rewrite: { uri }` only when `rewriteUri` is set.

**Form UI (`VirtualServiceForm.tsx`, same building blocks as `HTTPRouteForm.tsx`):**
- Identity (Name, Namespace; locked on edit).
- Hosts (required): rows with a `datalist` of Services in the namespace (`services` prop) plus free text; a ⚠ "missing" badge when the value is not a known Service and contains no `.`/`*` (external hosts are never flagged).
- Gateways: rows with a `<select>` of Istio gateways (`gateways.filter(g => g.type === 'istio')`, value `name` for the same namespace else `ns/name`) plus the fixed first option `mesh`; empty list means mesh-only.
- HTTP rules (required, at least one): per rule card — optional `name`; Match rows (URI type select + value, header rows name/type/value; "+ match", "+ header"); Route rows (destination host datalist from Services, subset datalist from `useSubsets(namespace)` filtered to subsets whose DR host resolves to the chosen host (compare short name and the `.ns.svc.cluster.local` form), port number, weight number) with the weight-sum hint when more than one route; optional Timeout (`e.g. 5s`), Retries (attempts + per-try timeout), Rewrite URI. Delete rule.
- Register in `registry.tsx` under `virtualservices.networking.istio.io` with `needsGateways: true, needsServices: true`.
- `web/src/api/subsets.ts`: `useSubsets(ns)` → `GET /api/subsets?ns=` → `{namespace, dr, host, name}[]`, `enabled: !!ns`, `staleTime: 30_000`.
