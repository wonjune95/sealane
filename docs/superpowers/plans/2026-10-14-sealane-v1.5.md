> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship v1.5.0: a sidecar-injection check in the mesh analysis (native sidecars included), findings that open the offending field in the editor, and a "mesh only" filter on the Services list.

**Spec:** Maintainer delegation 2026-10-14 ("desktop only; skip mobile; proceed with the rest by your judgment"). `docs/versioning.md` 1.x promise applies (additive only; the RBAC already grants namespaces and pods get/list).

### Task 1: Sidecar-injection finding

**Files:** `internal/api/snapshot.go`, `internal/api/analyze.go`, `internal/api/analyze_test.go`, `docs/features.md` (finding table row)

**Contract:**
- Snapshot pods become `[]podInfo{ns, name string; labels labels.Set; sidecar bool; injectOptOut bool; phase string}` where `sidecar` is true when any entry of `spec.containers` **or `spec.initContainers`** (Kubernetes native sidecars, which Istio ≥ 1.22 uses when `ENABLE_NATIVE_SIDECARS` is on) is named `istio-proxy`, and `injectOptOut` is true when the pod has label or annotation `sidecar.istio.io/inject: "false"`. Keep `anyPodMatches` working on the label sets.
- Snapshot gains `namespaces []nsInfo{name string; injection bool}` from a Namespaces list (`loadMeshSnapshot` opts `namespaces`; failure → nil → check skipped), where `injection` is true when the namespace has label `istio-injection=enabled` or any `istio.io/rev` label.
- New finding code `namespace-injection-no-sidecar`, severity **warning**, `Resource: ref{TypeID: "namespaces", Kind: "Namespace", Namespace: "", Name: <ns>}` (not a managed kind; the UI renders it without a link), one finding per namespace: when the namespace has injection on and at least one pod in phase `Running` has `!sidecar && !injectOptOut`. Message: `<n> running pod(s) without a sidecar in an injection-enabled namespace: a, b, c` (first three names, then ` +k`). Pods in `Succeeded`/`Failed`/`Pending` are ignored. Only reported when the pods list is available and the namespaces list is available; namespaces whose injection is off produce nothing.
- `Checked` counts namespaces with injection on as resources checked.

- [ ] Tests (RED first, `go test ./internal/api/ -run TestAnalyzeInjection -v`): (a) injection ns with one pod having `istio-proxy` as an init container and one without → one finding naming only the second pod; (b) a pod with the opt-out label → no finding; (c) a namespace without the label → nothing; (d) pods Forbidden → no finding and `Skipped` still `["pods"]`; (e) `ns=` filter: the finding's Resource.Namespace is `""` so scope it by Name — a finding for namespace X is reported when `ns == ""` or `ns == X`.
- [ ] Implement; `TestSnapshotListsEndpointsOnce` keeps passing (one more list: namespaces, for analysis only — flow map and route check do not request it).
- [ ] `docs/features.md`: add the row to the finding table with the native-sidecar note.
- [ ] Commit: `Analysis: warn about running pods without a sidecar in injection-enabled namespaces`.

### Task 2: Findings open the offending field

**Files:** `internal/api/analyze.go` (+ tests), `web/src/api/analyze.ts`, `web/src/components/FindingList.tsx`, `web/src/pages/ResourceEdit.tsx`, `web/src/components/YamlEditor.tsx`, `web/src/lib/yamlFocus.ts` (new), `web/tests/editor-focus.mjs` (new), `web/tests/analysis.mjs`, `web/tests/README.md`, `package.json` (`test:editor-focus`, `test:ui`), i18n

**Contract:**
- `finding` gains `Path string \`json:"path,omitempty"\`` (JSONPath-like, e.g. `spec.http[1].route[0].destination.subset`) and `Value string \`json:"value,omitempty"\`` (the offending scalar). Set them for: `vs-host-missing` (`spec.http[i].route[j].destination.host`, the host), `vs-subset-undefined` (`…destination.subset`, the subset), `vs-gateway-missing` (`spec.gateways[i]`, the gateway), `httproute-backend-missing` (`spec.rules[i].backendRefs[j].name`, the name), `dr-subset-no-pods` (`spec.subsets[i].name`, the subset name), `dr-host-missing` (`spec.host`, the host), `gateway-selector-no-pods` (`spec.selector`, the selector as `k=v` joined by `,`). tls/tcp routes use `spec.tls[i]` / `spec.tcp[i]` accordingly. Other codes leave them empty.
- `FindingList` resource link becomes `/resources/{typeId}/{ns}/{name}?focus=<encoded path>&value=<encoded value>` when `path` is set. For `Namespace` resources render plain text, no link.
- `web/src/lib/yamlFocus.ts`: `findFocusLine(yaml: string, path: string, value?: string): number | null` — walk the path through the YAML **text** by indentation: for each segment, from the current line onward find the next line at the expected indent whose key matches (`key:` for object keys; for `[i]` count `- ` items at the expected indent); return the 1-based line of the final key, or, when `value` is given and the final line does not contain it, the first following line containing `value`; `null` when any step fails. Ponytail: a text walk, not a parser — fine for the YAML the app itself dumps (two-space indent, block style).
- `ResourceEdit.tsx`: when `?focus=` is present and the YAML is loaded, switch to the YAML tab, compute the line, scroll it into view and apply a line highlight via a CodeMirror `Decoration.line` with class `cm-focus-line` (CSS in `index.css`: amber background, fades after ~3 s via a CSS animation); show a small banner `t('editor.focusBanner', { path })` with a dismiss button; if the line is not found show `t('editor.focusNotFound', { path })`. `YamlEditor.tsx` exposes a prop `focusLine?: number` that drives the decoration and scrolling.
- Tests: Go — assertions on `Path`/`Value` for the listed codes (extend existing analyze tests). Browser — `editor-focus.mjs`: fixtures as in `vs-form.mjs`; open `/resources/virtualservices.networking.istio.io/shop/reviews?focus=spec.http[0].route[0].destination.subset&value=v9` → YAML tab active, the highlighted line's text contains `subset: v9`, the banner is visible; a `focus` with a bad path shows the not-found banner. `analysis.mjs`: assert the resource link href contains `?focus=` for a fixture finding with `path`. Add to `test:ui`.
- i18n keys: `editor.focusBanner` "Showing {path}", `editor.focusNotFound` "Could not find {path} in the YAML", `editor.focusDismiss` "Dismiss" (and Korean).
- [ ] Commit: `Findings open the offending field in the editor`.
