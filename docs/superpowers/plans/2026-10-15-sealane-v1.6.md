# Sealane v1.6.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship v1.6.0: every analysis finding carries a remediation hint, the request console fills the URL from a Service picker (with the right port), and the Service page offers one-click "create a VirtualService / DestinationRule for this service" with prefilled templates.

**Architecture:** Hints are static per finding code, localized in the UI (the backend stays English-only data). The Service picker reuses `/api/services?ns=` (ports included). The create buttons link to the existing editor with query parameters that seed the new-resource template.

**Tech Stack:** Go 1.26, React 18, existing fixtures/Playwright. No new dependencies.

**Spec:** Maintainer: "continue with the next candidates" (2026-10-15). Desktop only. `docs/versioning.md` 1.x promise applies.

## Tasks

### Task 1: Remediation hints on findings (frontend only)
**Files:** `web/src/components/FindingList.tsx`, `web/src/lib/findingHints.ts` (new), `web/src/i18n/en.json`, `ko.json`, `web/tests/analysis.mjs`
- `findingHints.ts`: `hintKey(code: string): Key | null` mapping every backend code to an i18n key `hint.<code>`: `vs-host-missing` → "Create the Service, or fix the destination host (short names resolve in the VirtualService's namespace)." `vs-subset-undefined` → "Add the subset to a DestinationRule for this host, or remove it from the route." `vs-gateway-missing` → "Create the Gateway, or reference it as namespace/name." `vs-host-conflict` → "Merge the rules into one VirtualService, or give each a distinct host; Istio applies only one in an undefined order." `backend-no-endpoints` → "Check the backend's pods and readiness probes; nothing is ready to receive traffic." `httproute-backend-missing` → "Create the Service, or fix the backendRef name/namespace." `httproute-not-accepted` → "Check the Gateway's listeners and the route's parentRef (hostname, port, namespace policy)." `gateway-not-programmed` → "Check the GatewayClass controller and the listener configuration." `dr-host-missing` → "Create the Service, or fix the DestinationRule host." `dr-subset-no-pods` → "Label the pods to match the subset, or fix the subset labels." `gateway-selector-no-pods` → "Deploy the gateway workload, or fix the selector to match its pods." `namespace-injection-no-sidecar` → "Restart the listed pods so the sidecar is injected, or opt them out with sidecar.istio.io/inject: \"false\"."
- `FindingList.tsx`: under the message, a muted line `t(hintKey)` prefixed with a small "→" when a hint exists.
- `analysis.mjs`: assert the hint text for the fixture's `vs-host-missing` row.
- Commit: `Findings: a remediation hint per code`.

### Task 2: Service picker in the request console
**Files:** `web/src/pages/RouteCheck.tsx`, `web/src/api/services.ts` (reuse `useServices(ns)` or add `useServiceList`), i18n, `web/tests/routecheck.mjs`
- Next to the URL input: a namespace `<select>` (namespaces from `useNamespaces()`) and a Service `<select>` (`/api/services?ns=`) with a first option `t('rt.pickService')` ("Pick a service…"). Choosing a Service sets the URL to `http://<name>.<ns>.svc.cluster.local:<firstPort>/` (keeps any existing path); when the Service has several ports, a small port `<select>` appears beside it. The picker is optional: typing a URL still works and clears nothing.
- `routecheck.mjs`: mock `/api/namespaces` and `/api/services?ns=shop` (`reviews` ports `[9080, 9443]`); pick `shop`/`reviews` → URL input equals `http://reviews.shop.svc.cluster.local:9080/`; pick port 9443 → URL updates.
- Commit: `Request console: pick a Service to fill the URL and port`.

### Task 3: Create a VirtualService / DestinationRule from the Service page
**Files:** `web/src/pages/ServiceDetail.tsx`, `web/src/pages/ResourceEdit.tsx` (new-resource seeding from query params), i18n, `web/tests/editor-focus.mjs` or new `web/tests/service-create.mjs`
- Service page header actions: `t('services.createVS')` ("New VirtualService for this service") → `/resources/virtualservices.networking.istio.io/new?ns=<ns>&host=<name>`, and `t('services.createDR')` → `/resources/destinationrules.networking.istio.io/new?ns=<ns>&host=<name>`; visible to admin/editor only (`useCapabilities().role`).
- `ResourceEdit.tsx`: when creating and `ns`/`host` query params are present, seed the template with `metadata.namespace = ns`, `metadata.name = <host>` (VS) / `<host>` (DR), VS `spec.hosts = [host]` and the single route destination host `<host>`, DR `spec.host = <host>`; the seed must stay representable so the Form tab opens. Implement by post-processing the parsed template object (js-yaml load → set fields → dump) rather than string edits.
- Browser test: open the create URL with `?ns=shop&host=reviews` for both kinds → Form tab active, Name `reviews`, Namespace `shop`, Hosts/Host `reviews`; a viewer role sees no buttons on the Service page.
- Commit: `Service page: create a VirtualService or DestinationRule prefilled for the service`.
