# Sealane v1.7.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship v1.7.0 from the 2026-10-16 first-use walkthrough: the analysis flags a VirtualService destination port the Service does not expose, "New VirtualService for this service" seeds the Service's port, and page kickers are translated.

**Architecture:** The port check reuses the route check's rule (an explicit `destination.port.number` must be one of the Service ports) inside `analyzeSnapshot`; the editor seed gains a `port` query parameter; the kickers move to i18n keys.

**Tech Stack:** Go 1.26, React 18, existing fixtures. No new dependencies.

**Spec:** Walkthrough on the live cluster (2026-10-16): creating a VirtualService from the Service page for a Service on port 8080 produced a route with port 80; the route check flagged it ("Envoy will answer 503") but the analysis showed nothing; in Korean every page kicker ("Mesh analysis", "Request workbench", …) and the analysis "Namespace" label stayed English.

## Global Constraints
- Korean only in `web/src/i18n/ko.json`, `README.ko.md`, `docs/superpowers/`, `docs/announcement.ko.md`; every new UI string in both locales; `hack/check-i18n.sh`.
- Go scoped `./cmd/... ./internal/...`; `gofmt`, `go vet`, `go test` (+ `-race ./internal/api/`) before each commit. Frontend `cd web && npm run build && npm run lint && ../hack/check-i18n.sh`; `npm run test:ui` against the dev server.
- No new dependencies; no commit trailers; backend messages English; smallest working code.
- Finding codes and JSON fields are contracts shared with the UI and `hack/e2e.sh` (additive only).

## Tasks

### Task 1: Finding `vs-port-not-exposed` (Go)
**Files:** `internal/api/analyze.go`, `internal/api/analyze_test.go`, `web/src/lib/findingHints.ts`, `web/src/i18n/en.json`, `ko.json`, `docs/features.md`
- In the `vsDestinations` loop of `analyzeSnapshot`, after the Service is found (`ok`): when `d.Port != nil && d.Port.Number != 0` and no `svc.Spec.Ports[i].Port` equals it, add `finding{Severity: "error", Code: "vs-port-not-exposed", Resource: self, Service: svcKey(b), Path: d.path + ".port.number", Value: strconv.Itoa(int(d.Port.Number)), Message: fmt.Sprintf("destination %s does not expose port %d (service ports: %s)", svcKey(b), d.Port.Number, ports)}` where `ports` is the Service ports joined by ", ". A destination without a port is not checked (the route check handles the request-port case). ExternalName Services: skip (no ports to compare meaningfully) — follow how `noEndpoints` treats them.
- Test in `TestAnalyzeVirtualServiceDestinations` or a new `TestAnalyzePortNotExposed`: Service with port 8080, VS destination port 80 → one finding with the path `spec.http[0].route[0].destination.port.number`, value `80`; destination port 8080 → none; destination without port → none.
- `findingHints.ts` + both locales: `hint.vs-port-not-exposed` = "Use one of the Service's ports, or drop the port on a single-port Service." / Korean equivalent.
- `docs/features.md`: table row after `vs-subset-undefined`: `| \`vs-port-not-exposed\` | error | VirtualService | a destination's \`port.number\` is not a port of the Service (Envoy answers 503) |`.
- Commit: `Analysis: flag a destination port the Service does not expose`.
